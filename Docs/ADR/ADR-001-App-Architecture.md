# ADR-001: Feature-Based App Structure

## Status

Accepted

## Context

Приложение небольшое, но уже содержит две разные фичи: задачи и новости. Если хранить весь код в одной папке или переносить логику прямо в SwiftUI-экраны, проект быстро становится трудно читать и тестировать.

## Decision

Используем feature-based структуру:

- `App` для запуска приложения и верхнеуровневой навигации
- `Tasks` для моделей, бизнес-логики и экранов задач
- `News` для загрузки, кэша, маппинга и экранов новостей
- `HWmobileCore` для чистых моделей, DTO-маппинга, persistence и бизнес-логики без SwiftUI
- `HWmobileTests` для unit-тестов
- `HWmobileUITests` для UI happy-path и snapshot-теста
- `Docs/ADR` для архитектурных решений

## Consequences

Код проще объяснять на защите: каждая папка имеет понятную ответственность, а core-часть дополнительно отделена физическим Xcode framework target. UI остается тонким и зависит от `HWmobileCore`, но `HWmobileCore` не зависит от SwiftUI-экранов.
