# ADR-004: Unit Testing Strategy

## Status

Accepted

## Context

По критериям оценки тесты являются одним из главных признаков качества. Для текущего объема проекта важнее покрыть core-логику, а UI-тестами оставить только самые важные пользовательские сценарии.

## Decision

Добавлены targets `HWmobileTests`, `HWmobileUITests` и shared scheme `HWmobile`.

Покрываем unit-тестами:

- создание и валидацию задач в `TaskStore`
- изменение completion-state и удаление задач
- сохранение и загрузку задач в `TaskFileStore`
- поиск, фильтры и сортировку задач в `TaskListQuery`
- статистику задач в `TaskAnalytics`
- маппинг NY Times JSON в `NewsArticleDisplay`
- сохранение и чтение кэша новостей

Покрываем UI-тестами:

- создание задачи через настоящий экран приложения
- snapshot экрана задач как attachment в `.xcresult`

## Consequences

Unit-тесты проверяют основную бизнес-логику без ручного запуска UI. UI-тесты проверяют, что главный сценарий задач не сломан на уровне реального приложения.

Для защиты можно показать команду `xcodebuild ... test` и результат: 23 теста, 0 падений.
